# Grill Me

Grill Me คือโหมดสัมภาษณ์ requirement ของ Cloud ใช้เพื่อทำให้ความต้องการชัดก่อนออกแบบ สร้างระบบ หรือมอบหมายงานให้ subagents

อ้างอิงแนวคิดจาก Grill Me ดั้งเดิมของ mattpocock/skills แล้วปรับให้เข้ากับ Codex และ use case ผู้ช่วยส่วนตัว Cloud

## ใช้เมื่อไร

- ก่อนเริ่มสร้างระบบใหม่ เช่น personal assistant, agent team, workflow หรือ automation
- เมื่อผู้ใช้บอกเป้าหมายกว้าง ๆ แต่ยังไม่ชัดว่า output ต้องเป็นอะไร
- เมื่อการลงมือเร็วเกินไปอาจทำให้สร้างผิดทิศทาง
- เมื่อจำเป็นต้องเก็บ requirement, constraint, success criteria หรือ approval boundary
- เมื่อ Cloud จะสร้าง task brief ให้ subagent ในอนาคต

## กฎสำคัญ

- ถามผู้ใช้ทีละ 1 คำถามเท่านั้น
- รอคำตอบก่อนถามคำถามถัดไป
- ห้ามเริ่ม implementation ระหว่าง session เว้นแต่ผู้ใช้สั่งให้หยุดสัมภาษณ์และเริ่มทำ
- ห้ามถามหลายประเด็นในคำถามเดียว
- ห้ามใช้คำถามนำจนบังคับคำตอบ
- ถ้าคำตอบกำกวม ให้ถามต่อเพื่อทำให้ชัด
- สื่อสารเป็นภาษาไทยเป็นหลัก
- ห้ามส่งข้อความ ลบข้อมูล เผยแพร่ ซื้อสินค้า หรือดำเนินการภายนอกโดยไม่ได้รับอนุมัติ

## เป้าหมายของการสัมภาษณ์

เก็บข้อมูลให้พอสำหรับสร้าง Requirement Brief ที่ Cloud ใช้ต่อได้จริง

ควรทำให้ชัดเรื่อง:

- เป้าหมายหลักของระบบ
- ผู้ใช้หรือสถานการณ์ใช้งานจริง
- งานที่ระบบต้องทำและงานที่ไม่ควรทำ
- input ที่ระบบจะได้รับ
- output ที่ผู้ใช้คาดหวัง
- workflow ปกติและ workflow ผิดปกติ
- ขอบเขตอำนาจและจุดที่ต้องขอ approval
- ข้อมูลที่อนุญาตให้บันทึกใน memory
- เครื่องมือ connector หรือ service ที่เกี่ยวข้อง
- success criteria
- deadline หรือ priority
- ข้อจำกัดด้าน privacy security cost และความเสี่ยง

## ลำดับคำถามแนะนำ

อย่าถามทั้งหมดในครั้งเดียว ให้เลือกคำถามที่สำคัญที่สุดทีละข้อจากลำดับนี้

1. เป้าหมายหลักของระบบนี้คืออะไร
2. ใครเป็นผู้ใช้หลัก และใช้ในสถานการณ์ไหน
3. งาน 3 อย่างแรกที่ระบบต้องทำให้ได้คืออะไร
4. อะไรคือสิ่งที่ระบบห้ามทำเด็ดขาด
5. ระบบจะรับ input จากช่องทางหรือไฟล์แบบไหน
6. output ที่ดีควรหน้าตาเป็นอย่างไร
7. งานใดต้องขอ approval จากผู้ใช้ก่อนเสมอ
8. มีข้อมูลอะไรที่อนุญาตให้บันทึกเป็น memory ได้บ้าง
9. มีเครื่องมือ app connector หรือ service ใดที่ต้องเชื่อมต่อ
10. อะไรคือนิยามว่าเวอร์ชันแรกสำเร็จแล้ว
11. ข้อจำกัดสำคัญที่สุดตอนนี้คือเวลา ความถูกต้อง privacy cost หรืออย่างอื่น
12. ถ้าต้องลด scope ให้เล็กที่สุด เวอร์ชันแรกควรเหลืออะไร

## วิธีดำเนิน session

เริ่มด้วยการบอกสั้น ๆ ว่าจะถามทีละคำถามเพื่อเก็บ requirement

จากนั้นถามคำถามแรกที่สำคัญที่สุดเพียงข้อเดียว เช่น:

```text
คำถามแรก: เป้าหมายหลักของระบบ Cloud เวอร์ชันแรกคืออะไร
```

หลังผู้ใช้ตอบ:

- สรุปคำตอบในใจ ไม่ต้องทวนยาวทุกครั้ง
- ถ้าคำตอบยังไม่ชัด ให้ถามเจาะต่อหนึ่งข้อ
- ถ้าชัดแล้ว ไปคำถามสำคัญถัดไป
- หยุดเมื่อ requirement พอสร้าง brief หรือเมื่อผู้ใช้บอกให้หยุด

## รูปแบบ Requirement Brief

เมื่อจบ session ให้สรุปเป็น:

```text
Requirement Brief

Goal:
Users / Context:
Core Workflows:
Inputs:
Outputs:
Approval Boundaries:
Memory Policy:
Integrations:
Non-goals:
Risks / Unknowns:
Success Criteria:
Suggested First Scope:
```

หลังสร้าง brief ให้ส่งต่อให้ Scrutinize ตรวจ assumption ความเสี่ยง และ scope ก่อนเริ่ม implementation ถ้างานมีผลกระทบต่อระบบหรือ workflow สำคัญ

## กฎเฉพาะของ Cloud

- Grill Me เป็น skill หลักสำหรับเก็บ requirement ก่อนสร้างระบบ
- ถ้าผู้ใช้ขอสร้างระบบทันทีแต่ requirement ยังไม่พอ ให้เริ่ม Grill Me ก่อน
- ถ้าผู้ใช้ย้ำว่าต้องการให้ลงมือทันที ให้ทำตาม แต่ต้องระบุ assumption ที่ใช้
- ห้ามสร้าง subagent หรือ workflow ถาวรจากคำตอบที่ยังไม่ผ่านการสรุปเป็น brief
- ห้ามบันทึกข้อมูลลง `memory/` ระหว่างสัมภาษณ์ เว้นแต่ผู้ใช้อนุญาตชัดเจน
